# Guidance for visiting GPTs — The Unanswered Referral

## How this owner uses GitHub and the Project Museum

**This repository is a published work, not merely a store of Markdown files.** Its existing `index.html`, linked HTML readers, interactive exhibits and GitHub Pages site are often the intended public experience. Markdown, transcriptions, raw data and source code are the maintained supporting materials, not automatically the best links for a museum visitor.

The [TitanicParker Project Museum](https://titanicparker.github.io/) is a **curated entrance to published works**, not a plain repository index. When recommending an exhibit or building museum navigation:

1. **Website first:** inspect the relevant existing HTML presentation and its public navigation. Link visitors to a functioning published reading room/exhibit where one exists. Do not replace a finished public experience with a GitHub `blob/main/*.md` link merely because Markdown is easier to read programmatically.
2. **Source second:** include a clearly labelled source/research link separately when it helps verification, editing, evidence or audit.
3. **Curate, don't duplicate:** preserve the existing web exhibits and interactions; group related works, distinguish current controlling accounts from exploratory/historical work, and offer clear reader routes. Do not turn the museum into a wall of file links or a stack of repetitive project banners.
4. **Respect the present work:** begin with current controlling formulations. Consult older repositories **selectively** for genuinely useful overlooked insights, demonstrations, evidence or counterarguments; do not resurrect superseded mistakes or repeat broad historical archaeology.
5. **Do not confuse public accessibility with publication approval.** Verify links, actual rendered pages, mobile usability and sensitive-content decisions before featuring or embedding materials. Do not claim browser or deployment verification without a successful check.
6. **Do not publish or modify without authorisation.** Keep proposed museum content distinct from revisions to the underlying intellectual or documentary work.

A future GPT entering this repository should identify **what the visitor actually sees at the deployed website** before proposing repository or museum changes. This guidance concerns publishing and curation; it is not a new theoretical definition or a new evidential finding.

## Case-specific instructions

- Start with the existing published [The Unanswered Referral website](https://titanicparker.github.io/the-unanswered-referral/) and its `index.html` and `supporting.html` readers. The principal public narrative is `THE_UNANSWERED_REFERRAL.md`; the detailed counsel counterpart is [Prima Facie](https://titanicparker.github.io/prima-facie/). Treat their **HTML reading rooms as primary visitor destinations**, source documents as secondary evidence links.
- The current documentary question is whether the relationship between painful abnormal feet/toe clawing and neurological movement was adequately examined, communicated and followed up, including allocation of responsibility. Acknowledge the hospital's substantial neurological investigation, Parkinsonism diagnosis, podiatric involvement and treatment. Do **not** present negligence, misconduct, a single clinical cause or legal liability as established.
- Distinguish authenticated originals, working transcriptions, later testimony, clinical inference, counsel argument, unanswered questions and independent expert opinion. Explicitly identify what could support **or defeat** a proposition.
- Do not publish, reproduce, embed or promote sensitive clinical photographs, private family correspondence (including the October 2017 email), full clinical source collections or signed testimony without a specific privacy/editorial decision. A file already being public on GitHub does **not** constitute approval to feature it in the museum.
- If asked what strong points have been lost, selectively review older source-linked case work for *specific* overlooked documentary details or fair counterarguments. Important candidates include the original referral-versus-final-answer comparison; clinical foot/movement findings and later reassessment; who received information and owned follow-up; the differing September 2025 outcome representations; and uncertainty in the date/corroboration of reported bedside protest. Do not inflate these into established wrongdoing.
- Avoid automatically directing public visitors to raw case Markdown, the full clinical transcription or exhibit photographs. Send them first to the relevant **published explanatory page**, then provide controlled source links appropriate to the audience.

## Museum and companion essays

A plain-language, approximately 1,000-word HTML essay on neglected arguments should be a balanced **published companion reading experience** with an accessible HTML route, exact public supporting references and clear source-status limitations. If authorised, integrate it into the existing case website before adding the finished page to the Museum; do not substitute a bare Markdown link or silently publish sensitive exhibits.
